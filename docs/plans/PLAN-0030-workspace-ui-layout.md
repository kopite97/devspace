# Plan: 웹 전반의 UI 배치와 정보 밀도 정리

Status: `completed`
Date: 2026-10-13

## Goal

주요 화면에서 실제 데이터와 자주 사용하는 동작에 빠르게 도달하도록 불필요한 장식·빈 표시·중복 안내를 줄이고 헤더·필터·액션·본문의 배치를 정리한다. 실제 화면을 둘러본 [점검 기록과 캡처](../reviews/plan0030-ui-layout-audit/readme.md)를 근거로 한다. 디자인 선호에 따른 개선 제안과 기능 결함을 구분한다.

2026-10-13 사용자의 명시적인 승인에 따라 구현을 시작했다. PLAN-0028·0029는 completed, PLAN-0025는 기존 proposed 상태를 유지한다.

## Scope

- In scope:
  - 인증된 Home·프로젝트 목록/상세·작업 보드·개발일지 목록·자료실의 헤더, 툴바, 카드, 안내 및 공통 장식.
  - 공유 TaskBoard의 좁은 공간 대응과 빈 메타정보 처리, 프로젝트 상세 포커스, 프로젝트/링크 입력 모달의 간격·액션 접근성.
  - 상태·포커스·모바일 회귀 검증과 동일 데이터 전후 캡처.
- Out of scope:
  - 로그인 재설계, 개발일지 상세의 재개편, Document Viewer/Editor 본문·BlockNote·저장 흐름 변경.
  - API·조회 키·TTL·revision·cursor·세션·실제 업무 데이터 변경, 새 의존성 도입.
  - 사용자의 저장된 위젯 삭제·순서 강제 변경, 배포 기능 구현, 모든 검색 UI를 모달로 바꾸는 확장.
  - 기능 삭제, 전체 사이트 테마 교체, PLAN-0025 잔여 작업 일괄 편입.

### 2. 공통 헤더와 액션

- `PageScaffold`에 명시적인 compact 표현 옵션을 두고 현재 인증 업무 페이지에서 적용한다. 모든 `.page-heading`을 전역으로 덮어써 legacy·로그인·Document 화면을 우연히 바꾸지 않는다.
- compact 헤더에서 `YOUR PERSONAL DEV SPACE`와 격자/pointer 장식을 제거하고 제목·필요한 한 줄 설명·액션만 배치한다. 무의미한 공통 설명은 제거하고 자료실 등에는 화면 목적에 맞는 짧은 설명만 남긴다.
- desktop은 제목 왼쪽/액션 오른쪽, mobile은 제목 다음 액션 행. 긴 제목과 여러 버튼은 자연스럽게 줄바꿈한다. 고정 높이와 `margin-top:38px` 정렬을 사용하지 않는다. 기본 샘플 기준 헤더 높이는 desktop 96~~128px, mobile 120~~168px를 목표로 하되 긴 콘텐츠를 자르지 않는다.
- 필터·검색·보조 액션은 헤더 바로 아래 하나의 툴바 그룹으로 모은다. 390px에서 개발 분야/프로젝트는 두 열, 검색은 다음 행 전체 폭으로 배치하고 320px 또는 긴 라벨에서 한 열로 전환한다. 레이블과 선택값을 유지한다.
- 프로젝트 추가·링크 추가·태스크 추가는 각 페이지의 상단 주 액션으로 배치한다. 공유 `ApiTaskManager`/`ApiLinks`는 페이지 조합용 액션 슬롯을 제공하되 상태와 mutation은 feature 안에 둔다. Home 위젯·프로젝트 상세에서는 해당 섹션의 액션 위치를 유지한다. 한 화면에 동일 생성 handler를 가진 버튼/편집기 인스턴스를 중복 마운트하지 않는다.
- 액션 슬롯에는 실제 실행 버튼의 ref를 연결한다. `ApiTaskManager`의 내부 `.feature-actions button` 탐색에 의존하는 복귀 처리는 명시적인 실행 버튼 ref로 바꿔, 상단으로 생성 버튼을 옮긴 뒤 휴지통으로 포커스가 돌아가지 않게 한다. 생성 취소/저장 후에는 생성 버튼, 편집 후에는 기존 항목 제목으로 복귀하며 항목이 사라졌으면 생성 버튼을 사용한다. 실행 버튼도 제거·비활성화된 경우에는 해당 목록 제목으로 복귀한다. 링크의 기존 생성 버튼 ref도 상단의 실제 버튼에 연결하고 중복 포커스 복귀를 만들지 않는다.
- 개발일지의 검색·정렬 모달과 `새 글 작성`/`일지 작성`의 서로 다른 기능은 그대로 둔다. 모바일은 주 생성 액션과 보조 검색 액션을 읽기 쉬운 그룹으로 정리하고 숨기거나 합치지 않는다.

### 3. 작업 보드와 카드

- 현재 `.kanban`의 `repeat(3,minmax(240px,1fr))`는 의도된 내부 가로 스크롤이다. 이를 페이지 overflow 버그로 취급하지 않는다.
- viewport뿐 아니라 **실제 보드 컨테이너 폭**으로 판단해 약 760px 미만에서는 할 일→진행 중→완료의 세로 상태 섹션으로 바꾼다. 넓은 보드는 기존 세 열을 유지한다. 좁은 Home 위젯도 동일 기준을 사용한다.
- 빈 상태 섹션은 제목·건수·한 줄 안내만 남기고 다른 열 높이에 맞춰 불필요하게 늘리지 않는다. 각 상태의 더 불러오기·로딩·오류는 해당 섹션에 남긴다. 새 상태 탭이나 조회 요청은 추가하지 않는다.
- 태그가 공백이면 Badge를 렌더링하지 않고, 태그와 높은 우선순위가 모두 없으면 메타 행 자체를 제거한다. 제목·프로젝트·상태 선택의 간격을 정돈하되 제목/상태 조작의 44px 터치 영역을 유지한다.
- drag/drop, 상태 select, 진행 중 비활성, 제목 편집, 휴지통/복구, Home 위젯별 표시 개수와 API 정렬을 보존한다. 모바일 상태 변경은 기존 select로 완결되어야 한다.

### 4. 프로젝트 상세

- `ProjectDetailLayout`의 전체 컨테이너 `.focus()`를 페이지 제목의 프로그램 포커스로 바꾼다. 프로젝트 경로 진입마다 한 번만 지속적으로 마운트된 제목에 포커스하고, 로딩 중에는 로딩 제목을 사용한다. 데이터 도착·404·오류에서는 제목/상태 안내만 갱신하며, 재시도·백그라운드 갱신·편집 후에는 포커스를 다시 이동하지 않는다. 제목에 `tabIndex=-1`과 국소적인 포커스 표시를 제공하고 전역 `outline:none`으로 문제를 가리지 않는다. 재조회로 포커스된 연결 섹션이 제거될 때만 제목으로 복귀하며, 다른 살아 있는 조작 요소의 포커스는 유지한다.
- 목록 복귀와 편집을 compact 헤더에 둔다. 설명/상태를 기본 정보 상단에 묶고, 짧은 값은 desktop 다열·mobile 레이블/값 행으로 정리한다. 긴 목표·URL은 전체 폭에서 줄바꿈한다. 미등록 값도 간결하게 표시하며 정보를 숨기지 않는다.
- 마일스톤·연결 작업·최근 일지의 제목/건수/추가 동작을 섹션 툴바로 묶는다. 기존 섹션 순서·최근 일지 3개 계약과 보관 프로젝트의 생성 제한을 유지한다.
- 섹션 이동 버튼은 조건부 개선으로 둔다. 기본 정보 압축 후 390px/320px에서 연결 섹션까지의 거리와 스크롤 부담을 먼저 비교한다. 이동 부담이 남고 버튼 도입으로 상단 높이·줄바꿈이 과도하게 늘지 않을 때만 기본 정보/마일스톤/작업/일지 이동을 제공하며, 도입 여부와 비교 근거를 기록한다. 기본 정보는 실제 렌더링될 때, 연결 섹션은 기존 `verified` 조건(`ready && !stale`)으로 마운트된 경우에만 버튼을 제공한다. ref로 제목 포커스·스크롤만 이동하고 URL·이력·API·현재 편집 상태를 변경하지 않으며 reduced motion을 존중한다.

### 5. 자료실과 입력 모달

- 자료실의 중복 `개발 레퍼런스` 소개 블록을 제거하고 의미 있는 안내는 페이지 설명으로 합친다. `링크 추가`는 상단, 새로고침/활성 필터 초기화는 목록 툴바에 배치한다.
- 연결 프로젝트/개발 분야는 각 링크 제목 바로 아래로 옮기고 편집·삭제·순서 이동은 같은 항목의 보조 액션 그룹으로 묶는다. 모바일에서는 다음 줄로 감싼다. 전체 행을 링크로 감싸 중첩 버튼을 만들지 않는다.
- 순서 변경 가능 조건·충돌 복구·확인 절차를 유지한다. 순서 안내는 짧은 설명과 필요 시 펼칠 수 있는 도움말로 정리한다. 재정렬이 불가능한 이유와 오류는 숨기지 않는다.
- `ApiLinkEditor`의 `link-fieldset`에 일정한 필드 간격을 부여한다. 프로젝트 설명 textarea는 작은 화면에서 초기 높이를 약 96px로 줄이고 입력·resize를 허용한다.
- 프로젝트 모달은 먼저 필드 간격·설명 초기 높이만 조정하고 작은 화면에서 스크롤·키보드로 입력/저장/취소에 도달할 수 있는지 확인한다. 최초 화면에 저장 버튼이 보이지 않는다는 이유만으로 구조를 변경하지 않는다. 필드 가림이나 액션 접근 문제가 남아 재현된 경우에만 제목/본문/액션을 구분하는 opt-in 하단 액션 구성을 적용하고 재현 조건과 결과를 기록한다. 적용 시 하나의 본문 스크롤을 사용하고 저장/취소가 필드를 덮지 않게 한다. 공유 Modal의 기본 동작은 보존하며 검색·링크 등 짧은 모달을 일괄 변경하지 않는다.
- 키보드/가상 키보드·오류 설명·중첩 카테고리 관리·dirty guard·focus trap·닫은 뒤 포커스 복귀를 유지한다.

### 6. 홈과 앱 셸의 불필요한 요소

- 사이드바 하단의 홍보 카드(`workspace-note`)와 업무 페이지 하단의 두 슬로건을 제거한다. 작업실 이름·사용자 프로필·계정 메뉴·로그아웃·개발 분야 탐색은 유지한다.
- 초기화 완료 후 홈 하단의 중복 위젯 추가 유도 영역을 제거하고 상단 액션을 유지한다. 미초기화/빈 홈에서는 기존 시작/추가 진입점을 유지하여 빈 화면을 만들지 않는다.
- `availability=unavailable`의 `NOT_CONFIGURED`는 미설정 안내로 구분해 간결하게 표시한다. 원인 코드는 필요 시 세부 정보로 제공하고 실제 조회 오류의 재시도·경고와 구분한다. 연동할 수 없는 상태에서 동작하지 않는 설정 버튼을 새로 만들지 않는다.
- 저장된 6개 기본 위젯, 배치·크기·revision·설정·데이터는 그대로 유지한다. 배치가 어색하다는 이유로 서버에서 위젯을 삭제하거나 새 기본 레이아웃을 덮어쓰지 않는다.
