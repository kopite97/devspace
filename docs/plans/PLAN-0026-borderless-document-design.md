# Plan: 경계가 드러나지 않는 Document 글쓰기 화면

Status: `completed`
Date: 2026-09-23

## Goal

Document 글쓰기 화면을 제목과 본문이 페이지 배경 위에 자연스럽게 이어지는 형태로 보완한다. 글을 추가할 때 외곽 상자가 커지는 인상을 없애고, 내용의 길이와 관계없이 일정한 본문 너비와 좌우 여백을 유지한다.

사용자가 언급한 노션·티스토리는 경계 없는 글쓰기 경험의 방향으로 해석한다. 특정 서비스의 화면을 그대로 복제하지 않고 현재 앱의 색상·서체·탐색 구조에 맞춘다. 이번 요청은 계획 작성이며 구현은 시작하지 않는다.

## Scope

- In scope:
  - `/documents/:documentId/edit`의 제목·본문 외곽, 배경, 너비와 여백.
  - `/documents/:documentId`에도 같은 본문 정렬과 경계 없는 스타일을 적용해 편집·미리 보기 전환의 일관성 확보.
  - 저장 상태·상단 액션·첨부 영역의 정렬 및 모바일 대응.
  - 빈 문서·긴 문서·표·이미지에서 시각 및 편집 조작 회귀 확인.
- Out of scope:
  - API, DTO, 자동 저장·게시·첨부·권한·세션 정책 변경.
  - 편집기 교체, 새 패키지, 새 테마, 전체 화면 모드, 커버 이미지 기능.
  - Journal 목록과 상세 화면, 공통 Sidebar/Header의 재설계.

## Changes

### 1. 현재 구조와 원인

[DocumentWorkspace](../../src/features/documents/DocumentWorkspace.tsx)의 `article.document-paper`가 제목과 BlockNote 본문을 감싼다. [Document styles](../../src/features/documents/styles.css)에서 이 요소에 별도 surface 배경, 1px 테두리, 12px 모서리, 최소 높이 520px을 적용하고 있다. `.document-surface`의 최대 너비는 1080px이다.

[기존 화면](../reviews/plan0025-document-editor/editor-desktop.png)에서는 내용이 늘어날수록 카드 외곽의 하단 경계도 내려간다. 확인된 문제는 내용 높이에 따라 늘어나는 카드의 시각적 경계이며, 입력마다 가로 너비가 늘어나는 현상은 별도로 재현·확인한다.

### 2. 페이지와 이어지는 글쓰기 영역

- `.document-paper`의 테두리·둥근 모서리·별도 배경을 제거하고 그림자를 두지 않는다. BlockNote의 본문 배경도 투명하게 유지한다.
- 제목·본문을 둘러싼 상시 입력 테두리를 두지 않는다. 키보드 사용자가 위치를 알 수 있도록 제목의 `:focus-visible` 표시와 편집 커서는 유지한다.
- 바깥 카드 대신 글자 크기, 행간, 제목과 본문 사이의 여백으로 위계를 표현한다. 기존 테마 토큰과 Pretendard를 사용한다.
- 코드 블록, 표 셀, 인용, 파일 블록, 선택·드롭 표시, 팝업에는 각 기능을 식별하는 배경과 경계를 유지한다. 모든 하위 요소의 border를 일괄 제거하지 않는다.

### 3. 내용에 흔들리지 않는 너비와 스크롤

- 데스크톱 본문 열은 최대 800px을 기준으로 가운데 정렬한다. 제목·본문·첨부 영역의 실제 텍스트 시작선을 맞추며 BlockNote 기본 padding과 중첩되어 여백이 두 번 생기지 않도록 조정한다.
- 가용 너비가 줄면 유동적으로 축소한다. 모바일에서는 화면 좌우 16–24px 범위의 기본 여백과 블록 핸들용 공간을 확보한다. 핸들이 잘리지 않도록 실제 BlockNote DOM 기준으로 검증한다.
- 본문 높이는 내용에 따라 자연스럽게 증가하고 기존 페이지 스크롤을 사용한다. 고정 높이와 내부 세로 스크롤로 글쓰기 영역을 가두지 않는다.
- 빈 문서에서도 첫 입력 위치가 분명하고 클릭할 여유가 있도록 본문 최소 높이와 하단 여백을 둔다. 카드 크기를 강조하던 외곽 최소 높이는 제거하거나 본문 여백 역할로 정리한다.
- 긴 URL·제목·파일명은 가용 폭을 넘지 않게 처리하고 이미지는 본문 폭에 맞춘다. 넓은 표·코드의 필요한 가로 스크롤은 해당 블록 내부로 제한한다.

### 4. 주변 UI와 변경 파일

- 상단 돌아가기·저장 상태·미리 보기·게시·삭제 액션을 유지하고 본문과의 간격을 조정한다. 모바일에서는 버튼이 자연스럽게 줄바꿈하며 입력 영역을 가리지 않게 한다.
- 저장 오류, 게시된 문서 안내, 업로드 상태는 읽을 수 있는 별도 알림으로 유지한다. 첨부 안내·다운로드는 본문 아래 동일한 정렬 체계를 사용한다.
- 주 변경 파일은 `src/features/documents/styles.css`다. 편집/보기 상태 구분이나 정렬용 wrapper가 필요할 때만 `DocumentWorkspace.tsx`를 최소 수정한다. BlockNote 내부 DOM 조작이나 editor 재생성으로 스타일을 적용하지 않는다.
- 공통 app 스타일은 우선 수정하지 않고 Document 범위에 스타일을 한정한다. 변경 후 화면 증거는 `docs/reviews/plan0026-borderless-document-design/`에 기록한다.

### 5. 기존 계획과의 관계

[PLAN-0025](PLAN-0025-journal-document-editor.md)의 실제 연동 구현을 기반으로 하는 별도 디자인 계획이다. PLAN-0025의 미검증 항목이나 현재 `active` 상태를 이번 계획 작성으로 완료·취소 처리하지 않는다. PLAN-0026은 `proposed`로 등록하며, 실행 전 계획 상태 규칙에 맞게 기존 active 계획의 남은 검증과 실행 순서를 정리한다.

## Validation

### Static

- 계획 작성 단계: 새 계획·README의 상대 링크, Markdown 포맷, `git diff --check`를 확인한다. `npm run check:docs`의 기존 외부 경로 실패와 신규 링크 오류를 구분한다.
- 구현 단계: 변경 파일 포맷, `npm run build`, `npm run check:boundaries`, `git diff --check`를 수행한다.
- CSS 중심 변경에는 구현 내용을 그대로 확인하는 단위 테스트를 추가하지 않는다. controller/API 로직이 변경되지 않았는지 diff로 확인하고, 동작 검증은 기존 브라우저 흐름을 재사용한다.

### Runtime

- 같은 문서를 빈 상태 → 한 문단 → 여러 화면 길이의 본문으로 늘린 전후 화면을 비교한다. 모든 상태에서 제목·본문 외곽 상자가 보이지 않고 본문 열 너비와 좌측 시작점이 유지되어야 한다.
- 데스크톱 1440px·1280px, 모바일 390px·320px 및 200% 확대에서 화면을 직접 검토한다. 긴 텍스트·이미지·표·코드가 페이지 전체 가로 스크롤을 만들지 않는지 확인한다.
- 페이지 스크롤 하나로 마지막 문단에 도달하고, 긴 문서의 끝에서 입력할 때 커서가 화면 안으로 따라오는지 확인한다.
- 제목/본문 입력, 한글 IME, slash menu, formatting toolbar, block handle·drag, 이미지·파일 입력을 조작한다. 여백이나 overflow 변경으로 메뉴·핸들·포커스가 잘리지 않아야 한다.
- 편집 → 저장 → 미리 보기 → 재편집에서 본문 정렬이 일치하고 기존 저장·게시·첨부 기능이 동작하는지 기존 `tests/real/run.mjs --documents` 흐름으로 확인한다. 검증용 데이터는 기존 disposable 환경을 사용한다.
- 키보드 Tab 이동, 제목 focus-visible, 저장 상태·오류 안내, 모바일 액션 접근성을 확인한다. 로딩·오류 상태에서도 글쓰기 카드가 다시 나타나지 않게 확인한다.
- 변경 전후 동일 문서·viewport 스크린샷을 남기고 직접 비교한다. DOM/CSS 검사만으로 디자인 검증을 대체하지 않는다.
