# Plan: 전체 화면의 디자인 일관성과 가독성 개선

Status: `completed`
Date: 2026-10-21

## Goal

현재 구현된 화면의 기능과 정보는 유지하면서 글자 크기, 정보의 시각적 위계, 정렬선, 여백, 입력창과 버튼의 모양을 정돈한다. 기존 Warm Porcelain 배경, 짙은 사이드바, 파란 강조색, 문서의 borderless 표현을 유지한다. 새 테마나 기능을 도입하는 계획이 아니다.

2026-10-21 운영 사이트 `https://devspace.nellucia.dev`를 승인된 Chrome 브라우저 경로로 열어 로그인 전후 화면을 검토했다. 사용자가 직접 로그인했으며, 운영 데이터를 생성하거나 저장하는 동작은 검토 범위에 포함하지 않았다. 소스 검토 기준은 `aaeaaa1`이다. 운영 배포와 이 커밋의 일치 여부까지 검증한 것은 아니다.

이 문서는 디자인 구현을 위한 runtime PLAN이다. 2026-10-21 사용자 승인으로 구현을 시작했다. 다른 PLAN의 상태는 변경하지 않는다.

2026-10-21 재검토에서 공통 구분선 규칙과 검증 기준을 보완했다. 운영의 일지 목록·상세, 프로젝트 목록·상세를 다시 열어 확인했으며, 나머지 경계 조합은 현재 CSS와 실제 컴포넌트 조합으로 점검했다. 아래 관찰은 구현 전 검토 근거다.

  - 프로젝트 목록·상세·보관 목록, 카테고리 관리, 프로젝트·마일스톤 입력 화면.
  - 작업 보드, 일반/GitHub 작업 카드, 작업 입력·휴지통 화면.
  - 개발일지 목록·상세·검색/정렬·작성, 새 글 선택/생성 확인, 문서 Viewer/Editor의 외곽 UI.
  - 자료실 목록·빈 상태·링크 입력, GitHub 계정·저장소 연결/관리·Issue·동기화 설정·작업 결과.

- Out of scope:
  - API, 요청 수·시점, 쿼리 키·캐시·TTL, 인증/인가, URL·라우팅·브라우저 이력 변경.
  - 데이터 모델, 필터 값, 검색·정렬·페이지 크기, 저장·자동 저장·발행, 업로드, 복구, 확인창, 에러 처리 변경.
  - 버튼/필드/정보의 추가·삭제·통합, 동작을 새로운 메뉴나 접힘 영역 뒤로 이동하는 변경.
  - 위젯 초기화·저장된 순서/크기 변경, 작업 상태 전환 방식 변경, GitHub 연동/동기화/매핑/보호 규칙 변경.
  - 문구·상태명·날짜 형식·데이터 표시 의미 변경, BlockNote 기능·본문 구조 변경, 새 의존성·폰트 도입.
  - 디자인 검토 중 발견되는 기능 문제의 동시 수정, PLAN-0025의 잔여 기능/검증 작업 편입.

## Changes

### 1. 검토 범위와 근거

`PrivateWorkspace`의 실제 인증 경로를 기준으로 페이지를 식별했다. `routes.ts`만으로 목록을 만들면 GitHub 페이지가 빠지므로 두 파일을 함께 확인했다. 별도 URL이 없는 마일스톤·저장소 관리·모달은 상위 페이지의 하위 화면으로 포함한다.

### 3. 디자인 기준

- 기존 색채·아이콘·폰트 계열은 유지한다. CSS 토큰에 필요한 글자/행간/간격/컨트롤 규격만 추가하고 기존 기능별 의미 색을 바꾸지 않는다.
- 일반 본문·목록 제목은 14–16px, 조작부는 14px, 보조정보는 12–13px, 섹션 제목은 16–18px를 기본 목표로 한다. 모바일 입력은 16px, 페이지 제목은 기존 26–30px 수준을 유지한다. 모든 텍스트를 일괄 확대하지 않는다.
- 한글 본문/설명은 약 1.5–1.7의 행간을 적용한다. 긴 이름·URL·상태 메시지는 줄바꿈하며 새 말줄임·line-clamp로 정보를 숨기지 않는다. 기존 말줄임/접기 계약도 임의로 변경하지 않는다.
- 간격은 4/8/12/16/24/32px 단계를 기본으로 한다. 제목→설명, 레이블→입력, 관련 버튼끼리의 간격과 섹션 사이 간격을 구분한다.
- 업무 페이지의 제목·필터·섹션 시작선을 맞추고, 내부 패딩은 한 번만 적용한다. `content-panel`, `stats`, `project-list`, `feature-actions`의 누적 inset을 컨텍스트별로 정리한다.
- 기본 조작부는 desktop 약 40px, mobile 최소 44px를 목표로 하되 기존에 확보된 44px 영역을 축소하지 않는다. native select/checkbox의 동작과 접근성 의미는 유지한다.
- 기존 primary/secondary/ghost/danger 역할을 유지하면서 텍스트·테두리·상태별 대비를 통일한다. 선택된 기존 탭은 배경+테두리+글자 굵기로 구분한다. 비활성 이유/안내는 숨기지 않는다.
- 일반 텍스트 대비 4.5:1, 큰 글자·주요 컨트롤 경계/포커스 3:1을 검증 목표로 한다. disabled 상태도 식별 가능하게 유지한다. 포커스 표시를 없애거나 포커스 이동 로직을 변경하지 않는다.

#### 구분선과 테두리의 적용 원칙

- 하나의 정보 경계는 한 요소만 선을 그린다. 인접한 두 선 사이에 내용 없이 여백만 있으면 중복 후보로 판단한다. 선을 흐리게 하거나 간격을 늘려 중복을 감추지 않는다.
- 제목→본문은 헤더 아래 선, 행→행은 행 사이 선, 목록→하단 액션은 footer 위 선, 독립 섹션→섹션은 다음 섹션 위 선을 기본 담당으로 정한다. 같은 경계의 반대쪽 선만 해당 화면 범위에서 제거한다.
- 필터·집계·설명 등 실제 내용이 두 선 사이에 있으면 서로 다른 경계일 수 있다. 선의 개수만 세어 일괄 삭제하지 않는다. 섹션은 여백·제목으로 충분히 구분되는지도 함께 판단한다.
- `border`, `border-top/bottom`, `box-shadow`, 의사 요소가 만든 선을 함께 확인한다. 입력창·카드 외곽, 선택된 탭, 포커스·드래그 대상 표시, 사용자가 작성한 문서 본문의 구분선은 장식선 정리 대상에서 제외한다.
- 공유 `.content-panel`, `.document-row`, `.github-row`의 테두리를 전역으로 모두 없애지 않는다. 페이지/목록 컨텍스트로 범위를 제한하고 원본 규칙에서 정리한다. 음수 margin으로 선을 포개거나 DOM 순서를 바꾸지 않는다.

### 4. 화면별 적용

#### 공통 셸·로그인·홈

- 사이드바 항목과 작업실 정보의 글자 크기/행간을 정리한다. 폭·항목 수·순서·메뉴 열기/닫기·계정 메뉴 동작은 유지한다.
- 기존 compact 헤더의 상단 여백과 설명 간격을 맞춘다. 기능별 필터 개수나 배치를 다른 UI 방식으로 통합하지 않는다.
- 홈의 초기 안내와 시작 액션이 같은 시각적 영역으로 읽히도록 기존 컨테이너의 폭·padding·정렬만 조정한다. 버튼을 복제하거나 초기화 조건을 바꾸지 않는다.
- 위젯 화면은 제목·본문의 안쪽 정렬선, title typography, footer의 가독성을 통일한다. `.widget-small`의 이름을 억지로 더 작게 만드는 규칙을 줄인다. 저장된 grid span·순서·표시 개수, narrow board의 기존 세로 전환 기준은 유지한다.
- 로그인 왼쪽 workflow의 그룹 간 간격만 조정한다. 기술 선택/단계 선택·애니메이션·reduced motion·1023px 이하 표시 정책과 Google 로그인 흐름을 보존한다.

#### 프로젝트·작업·자료실

- 프로젝트 집계와 목록의 왼쪽 시작선을 정돈하고, 모바일 집계 레이블 영역을 같은 높이로 맞춰 숫자 기준선을 일치시킨다. 긴 레이블은 자르지 않는다.
- 프로젝트 기본 정보의 짧은 값은 기존 grid 안에서 균형 있게 배치한다. 목표·저장소 등의 전체 폭과 줄바꿈은 유지한다. 섹션 순서와 표시 조건은 변경하지 않는다.
- 마일스톤·작업·일지·GitHub 섹션의 제목/부가 설명/액션 간격을 같은 기준으로 맞춘다. 새 탭·앵커·접힘 기능을 도입하지 않는다.
- GitHub 상태 필터는 기존 위치와 동작을 유지한 채 시각적으로 다른 필터들과 어울리도록 스타일링한다. 작업 카드 제목/출처/태그/상태 영역의 크기·간격을 조정하고 출처 메타정보를 삭제하거나 이동하지 않는다.
- 자료실은 링크명/설명/분류와 관리 버튼 사이의 간격·baseline을 정리한다. 편집/위로/아래로/삭제는 항상 기존 조건대로 표시하며 새 overflow menu로 옮기지 않는다. 링크 순서와 외부 링크 동작을 보존한다.

#### 개발일지·문서

- 일지 목록의 겹친 구분선을 하나로 정리하고 모바일 행 안의 제목·메타·액션 간격을 줄인다. `일지 작성`과 `새 글 작성`, 검색/정렬 모달을 그대로 유지한다.
- 일지 상세의 제목/메타/설명/연결 글을 같은 폭에서 읽히도록 간격을 정돈한다. 연결 글의 시각적 경계선 중복을 제거하되 이동 버튼, 개수, 순서 안내와 기존 설명 접기는 보존한다.
- Viewer/Editor의 toolbar·안내문·본문·첨부 영역의 정렬 관계를 통일한다. 본문 최대 800px와 BlockNote의 block handle 공간은 유지한다. 모바일 toolbar의 줄바꿈을 자연스럽게 하고 모든 동작을 노출한다.
- 게시/초안/저장 상태 문구·첨부·오류를 기존 조건대로 유지한다. 에디터 내부 contentEditable, schema, 플러그인, toolbar 기능 및 autosave controller는 수정하지 않는다.

#### GitHub 계정·저장소 관리

- `GitHubPage`의 헤더 높이/글자/정렬을 다른 업무 페이지의 compact 규격에 맞춘다. `PageScaffold`의 `compact` prop은 기존 eyebrow 문구와 blueprint hook 적용도 바꾸므로 단순히 켜지 않는다. 화면 전용 스타일 class로 간격·크기만 조정하고 기존 문구/표시 조건/애니메이션 동작은 유지한다.
- 계정 상태 배지에는 내용 너비와 기존 badge radius를 적용한다. 계정 정보/안내/액션/해제 영역의 간격과 읽기 폭을 정리한다.
- 저장소 관리의 기존 Issue/동기화·설정/작업 결과 탭은 selected 스타일만 보강한다. 탭 상태, 데이터 요청, 상태 복원은 수정하지 않는다.
- Issue 번호 입력은 값의 특성에 맞는 최대 너비, 실행 버튼은 내용 너비를 기본으로 한다. 좁은 화면에서만 자연스럽게 쌓는다. ID 필터·페이지 크기·매핑 필드는 그대로 두고 입력창/label/group 스타일을 맞춘다.
- Issue 제목/상태·ID/원문/본문 disclosure와 작업 결과의 ID·결과를 글자 단계와 행간으로 구분한다. raw 상태 문자열·ID·timestamp를 번역/가공하지 않는다.
- sticky 선택 막대가 320/390px 및 확대 화면에서 기존 내용을 가리지 않도록 padding·줄바꿈·공간을 검토한다. sticky 동작·선택 상한·미리보기/가져오기 프로세스는 유지한다.

#### 공통 모달과 상태 화면

- 프로젝트·태스크·일지·링크·마일스톤·카테고리·위젯·저장소 연결 모달의 제목/첫 필드 간격, label, input, textarea, footer 규격을 통일한다.
- 일지 fieldset의 기본 테두리·margin·padding만 제거한다. 요소 자체나 disabled/role/label 연결을 제거하지 않는다.
- 태스크 상세 내용과 프로젝트 설명처럼 긴 내용을 입력하는 필드는 기존 순서를 유지하면서 desktop에서 전체 열을 사용한다. textarea resize를 유지한다.
- dialog의 max-height와 내부 스크롤·모달 footer 여백을 다듬는다. JS 스크롤 관리자, focus trap, Escape/backdrop 처리, confirm, 저장/취소 handler는 변경하지 않는다. 고정 footer는 기본안에 넣지 않는다.
- 로딩/빈/오류/404 상태의 문구·재시도 동작을 보존하면서 글자·컨테이너 padding·줄바꿈만 공통 기준으로 맞춘다.

## Validation

2026-10-21 잔여 실행 정리: 사용자의 PLAN 계속 실행 요청에 따라 자동 검증을 재개했다. Computer Use는 지정된 5173만 사용했고, 기존 격리 harness에서는 21건 문서 목록·다음 페이지 실패/재시도, GitHub 오류/부분 결과와 native 200% 모달 11종을 보완했다. 디자인 검증은 경계 표의 구조별 대표 상태와 기존 기능 회귀를 조합한다. 모든 오류 문자열·데이터·폭의 전체 곱을 시각 검사했다는 뜻은 아니다. 문서 기능 보존은 실제 자동 저장/발행/첨부/접근/이동/삭제/목록 검증인 `--document-ui`로 분리했다. 전체 `--documents`의 raw 대용량 API 요청 실패와 Nginx harness의 소스 모듈 import 실패는 별도 제한으로 유지하며, 이를 해결하기 위한 서버·문서 기능 변경은 이 디자인 PLAN에 편입하지 않는다.

2026-10-21 후속 지시: 추가 검토는 사용자가 지정한 기존 5173 화면에서 진행했다. 별도 서버와 자동 검사를 다시 실행하지 않고, 실제 화면에서 열기/닫기·선택 미리보기·모바일 스크롤을 확인했다. 이 과정에서 일지 선택/새 글 확인 모달의 간격을 추가 보정했다. 이전 자동 검사와 이번 직접 확인의 범위는 [검증 기록](../reviews/plan0033-design-consistency/validation.md)에 분리했다. 데이터가 없어 재현할 수 없는 상태를 만들기 위해 실사용 데이터를 변경하지 않는다.

### Runtime

구현 전후 같은 데이터·상태·브라우저 글꼴 로드 완료 조건으로 비교한다. 운영 환경에서는 읽기와 안전한 UI 열기/닫기만 사용하고, 저장을 포함한 기능 보존 검증은 기존 격리 테스트 환경에서 수행한다.

| 검증 축      | 대상과 기대 결과                                                                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 화면 범위    | 위 검토표의 모든 경로와 하위 UI를 포함한다. 이번에 운영 데이터가 없어 보지 못한 채워진 홈/자료실/마일스톤, 위젯·카테고리 모달도 격리 데이터로 확인                                               |
| 폭           | 1440/1280/1024/768/390/320px에서 핵심 페이지. 모바일 모달은 390×600 및 320px에서도 닫기/취소/저장에 도달                                                                                         |
| 타이포그래피 | 모바일 일반 입력과 검색 모달 모두 computed 16px, label·항목명·메타의 단계 일관성, 글자 확대 후 잘림 없음                                                                                         |
| 정렬         | 헤더/필터/본문 시작선 일관성, 모바일 집계 숫자 baseline, 과도하게 늘어난 GitHub badge/단일 실행 버튼 제거, 태스크 textarea 전체 폭                                                               |
| 구분선       | 위 경계 표의 각 조합에서 같은 경계를 표시하는 장식선은 최대 1개. 목록 0/1/여러 항목, 더 불러오기 유무, 로딩/오류, 저장소 접힘/펼침 및 탭별 상태를 비교. 서로 다른 정보 경계와 컨트롤 외곽은 유지 |

| 상태         | 빈/로딩/오류/비활성/선택/focus/외부 데이터 일부 비표시 안내를 확인. 안내문을 숨겨 레이아웃을 맞추지 않음                                                                                         |
| 반응형       | 페이지 전체의 의도치 않은 가로 스크롤·겹침 없음. 코드/표의 기존 내부 스크롤과 narrow board의 기존 세로 표시 보존                                                                                 |
| 키보드       | Tab 순서, visible focus, modal focus trap/닫기/복귀, 모바일 메뉴, 기존 journal 이동 버튼 동작 보존                                                                                               |

| 기능 보존    | 필터/검색/정렬/보관/작업 select·drag/drop/휴지통/모달 저장·취소/위젯 편집/문서 자동 저장·발행·첨부/GitHub 기존 상태 보호에 새 회귀 없음                                                          |

디자인 비교를 위해 운영 위젯을 초기화하거나 운영 링크·일지·작업을 생성하지 않는다. 데이터나 외부 접근 상태가 달라진 캡처는 디자인 전후의 동일 조건 비교로 사용하지 않는다. 검토 중 관찰된 GitHub 일부 데이터 비표시는 이 계획의 기능 수정 대상으로 삼지 않는다.

구분선 검증 기록에는 경계별 화면/상태, 유지한 선의 selector, 제거한 중복 selector, 동일 조건 전후 캡처를 남긴다. computed style에서 border가 없어졌다는 사실만으로 완료 처리하지 않고 그림자·의사 요소를 포함한 실제 화면을 확인한다. desktop과 390/320px, 200% 확대에서 같은 경계가 두 줄로 돌아오지 않아야 한다. 근거 표에서 검증 필요로 구분한 후보는 재현 결과에 따라 유지/정리 판정과 이유를 남긴다.
